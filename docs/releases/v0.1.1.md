# Echoo PGMQ v0.1.1

本版本发布 PR #12 的同 worker 持久化入队后定向唤醒，以及已接受 TCP socket 的
TCP_NODELAY。默认50ms polling、提交后 Accepted、租约 fencing 和背压不变。
跨 PostgreSQL backend 的 SQL 入队仍依赖周期 polling。

## 版本与兼容性

- 分发版本：0.1.1
- 原生构建版本：0.1.1
- SQL 扩展默认版本 / MANIFEST.extensionVersion：0.1.0
- 包内可用 SQL 版本：0.1.0、0.1.1；后者仍是可选、显式升级

不要以 GitHub Release/tag、安装包名称或 MANIFEST.version 推断数据库的 extversion。
机器消费者应读取 extensionVersion / sql_default_version；已安装数据库的实际 SQL
版本以 pg_extension.extversion 为准。安装新的原生二进制不会执行 ALTER EXTENSION，
本次发布没有把可选 SQL0.1.1 迁移设为必须，也没有改变 control 文件的默认版本。
旧 v0.1.0 包仍可由安装包验证器读取。既有 v0.1.0 tag/Release/资源保持不变。

## 性能证据与代价

[完整四组实验报告](https://github.com/MixGeeker/echoo_pgmq/blob/4500850b56668c2e9a4d7f22d3995d62d1c988b9/docs/performance/queue-wakeup-factorial-results-8a1347c6.md)

在持久化开启、默认50ms polling、同连接收发的合成 CI 测试中，Windows W1/W8/W32
receive P95 的三轮中位数为63.93→4.94ms、65.97→13.13ms、95.71→51.73ms。
但 Windows W32 等量消息的 worker CPU 开销增加31–75%；持续 backlog 吞吐没有
普遍提升。Linux W32 有一轮首批 P95 为153ms，该异常未被删除。

因此本版本是有 CPU 代价的稀疏消息延迟优化，不是吞吐、能耗或店端容量保证。
已修正实验逐臂核对实际安装的四种原生构建摘要，24个全新集群臂、26,304条消息
完成核对；旧 wake-only 负面结果和一次无效 Linux 安装身份实验也保留在报告中。

## 发布与验收边界

发布流程只接受本仓库 main 上固定提交的成功普通 CI，校验六平台/版本任务、
十二份候选包/证据 artifact、所有摘要、包内文件与来源，随后上传为 draft，
逐资源下载回验后才公开；不重建、不覆盖旧 tag 或资源。具体 source SHA、CI run、
普通测试执行数和资源摘要以本次 PROVENANCE 与 BINARY-MANIFEST 为准。

“正式发布”表示新版本在 GitHub Release 可获取，不表示生产/安全验收完成。
包继续标记 candidate-not-production-release、blocked_security_review，未签名。
Windows Server2022 CI 不是 Windows11、实际 ERP、店端存储或物理断电验收；
本版本尚未在用户真实 Win11 环境完成联测。没有执行新的安全/对抗/断电测试。

生产替换前必须完成自身备份、回退方案、依赖/ABI/ACL 和业务联测。
提供的 install_candidate.py 仅用于停止服务后的可丢弃 PostgreSQL 安装，
不是生产升级工具；详细步骤见 docs/admin.md、docs/quickstart.md 与包内说明。
