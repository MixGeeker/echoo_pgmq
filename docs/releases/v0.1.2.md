# Echoo PGMQ v0.1.2

本版本发布 PR #15：Linux arm64 原生候选包、管理员删除队列接口（可选 SQL 0.1.2），
以及 AMQP 消息嵌套深度上限的安全修复。默认 SQL 版本、提交后 Accepted、租约
fencing 和背压不变。

## 新内容

- **Linux arm64（aarch64）**：PG18/17/16 各一份 `linux-aarch64` 候选包，
  在 GitHub 原生 Arm runner（ubuntu-24.04-arm）上构建、打包并跑源码/归档重装两轮普通回归。
  x64 Linux 与原生 Windows 包继续提供。每个 PG 主版本、操作系统与架构必须使用对应包。
- **drop_queue（SQL 0.1.2，可选）**：`drop_queue(queue, missing_ok DEFAULT false)`
  在一个事务内删除队列及全部 ready/inflight/dead 消息、ACL 与幂等键，并同步扣减
  实例全局消息/字节计数，返回删除的消息数。仅管理员可执行；有事务正持有该队列消息
  行锁时立即以 55P03 失败且不改数据，调用方重试。
- **安全修复：AMQP 嵌套深度**：Proton 0.40 编解码器无深度上限地递归解码复合值，
  不足 1 MiB 的深层嵌套消息可耗尽 C 栈，使 worker 崩溃并触发整个 PostgreSQL 集群的
  崩溃恢复；经 AMQP 收件或 SQL `enqueue` 写入的消息都会经过该路径。现在消息先经
  有界遍历，嵌套超过 64 层（described/list/map/array 各计一层）直接拒绝，
  AMQP 返回 decode-error，SQL 写入的此类消息在投递时转为死信。

## 版本与兼容性

- 分发版本：0.1.2
- 原生构建版本：0.1.2
- SQL 扩展默认版本 / MANIFEST.extensionVersion：0.1.0
- 包内可用 SQL 版本：0.1.0、0.1.1、0.1.2；0.1.1 与 0.1.2 均为可选、显式升级
  （`ALTER EXTENSION echoo_pgmq UPDATE TO '0.1.2'`，0.1.0 经 0.1.1 链式升级）

不要以 GitHub Release/tag、安装包名称或 MANIFEST.version 推断数据库的 extversion。
机器消费者应读取 extensionVersion / sql_default_version；已安装数据库的实际 SQL
版本以 pg_extension.extversion 为准。安装新的原生二进制不会执行 ALTER EXTENSION。
嵌套深度上限在原生库中生效，与 SQL 版本无关。既有 v0.1.0/v0.1.1 tag、Release
与资源保持不变。

## 发布与验收边界

发布流程只接受本仓库 main 上固定提交的成功普通 CI，校验九个平台/版本任务
（Linux x64、Linux arm64、原生 Windows Server 2022 × PG18/17/16）、十八份候选包/证据
artifact、所有摘要、包内文件与来源，随后上传为 draft，逐资源下载回验后才公开；
不重建、不覆盖旧 tag 或资源。具体 source SHA、CI run、普通测试执行数和资源摘要以本次
PROVENANCE 与 BINARY-MANIFEST 为准。

合入前在 PR #15 最终提交上另行手动运行了 qualification（Linux/Windows × PG18/17/16，
含进程级崩溃恢复与 rhea 互操作）及 security 工作流（GCC 静态分析、Proton 与生产消息
校验器两组 ASAN/UBSAN 限时 fuzz），均通过。它们是补充证据，不构成完整安全资格。

“正式发布”表示新版本在 GitHub Release 可获取，不表示生产/安全验收完成。
包继续标记 candidate-not-production-release、blocked_security_review，未签名。
人工安全审查未完成；解码后节点数的内存放大仍只受 max_message_bytes 约束。
arm64 包未在实机 ARM 服务器或 Apple Silicon 上的 Linux 虚拟机做额外验收。
Windows Server2022 CI 不是 Windows11、实际 ERP、店端存储或物理断电验收。

生产替换前必须完成自身备份、回退方案、依赖/ABI/ACL 和业务联测。
提供的 install_candidate.py 仅用于停止服务后的可丢弃 PostgreSQL 安装，
不是生产升级工具；详细步骤见 docs/admin.md、docs/quickstart.md 与包内说明。
