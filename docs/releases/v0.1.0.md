# Echoo PGMQ v0.1.0 发布说明与隔离安装指南

Echoo PGMQ v0.1.0 是项目的正式公开发行版本，面向 PostgreSQL 原生持久队列的评估与集成。它在 PostgreSQL background worker 内提供基于双向 TLS 的 AMQP 1.0 接入，使用普通 WAL-logged 表保存完整消息编码，并提供可与业务更新同事务提交的 SQL 入队接口。

**正式公开发行不表示完成生产资格认证。** 本次为未签名分发，完整安全审阅与安全/故障资格仍待完成。项目所有者已报告自己的测试通过并授权正式发布，但没有给出可核验的测试范围；这不补足下面列出的未验证项目。建议先在可丢弃、与业务网络隔离的环境中使用合成数据评估，不直接覆盖现有 ERP PostgreSQL 安装。

## 版本与来源

- 公开版本：`v0.1.0`；默认扩展 SQL 版本：`0.1.0`
- 二进制的唯一源码提交：[`ef12d35447c7783f75ca123467208eb100533311`](https://github.com/MixGeeker/echoo_pgmq/tree/ef12d35447c7783f75ca123467208eb100533311)
- 二进制与原始普通回归证据：[GitHub Actions 36854708200](https://github.com/MixGeeker/echoo_pgmq/actions/runs/36854708200)
- PostgreSQL 18 为主要目标，16/17 为补充验证；每个主版本使用自己的二进制
- 本次将上述 CI 的六份原始内层 ZIP 原样分发，不重编译、不重打包，也不修改内层 `MANIFEST.json`

内层归档的 `status=candidate-not-production-release`、`qualification_status=blocked_security_review`、文件名中的 `candidate` 和构建时文档都保留。这些是原始构建身份与资格记录，正式 Release 不重写它们。发布 tag `v0.1.0` 严格指向二进制源码提交 `ef12d35447c7783f75ca123467208eb100533311`。发布流程和附带说明来自 provenance 单独记录的 automation commit；二进制源码、CI 运行和发布材料来源分别记录，不混为同一提交。

本次公开发行延续原生队列、受限 SQL 接口、AMQP 1.0 消息语义和已整合的 SPI 计划复用，补齐标准 Apache-2.0 项目许可及分发通知。没有加入 SQL 0.1.2 实验，也没有新增吞吐或业务延迟承诺。

## 已验证范围与限制

普通 CI 覆盖 Ubuntu 24.04 和原生 Windows Server 2022，各运行 PostgreSQL 18、17、16，共六组合。每组合包含源码安装与原始候选归档重装两轮：PG18 每平台每轮 45 项，PG16/17 每平台每轮 37 项，合计 **476 次普通测试通过，12 个 core.sql 完成标记**。这些是执行次数，不是 476 个不同测试。范围包括普通 SQL/storage、并发与配额、事务性 SQL 升级回滚、备份恢复、正常 AMQP 二进制/提交/重投/迟到 ACK/release 语义及归档核验；PG18 另含独立 Node/rhea 客户端互操作。

该普通清单不运行畸形协议、连接耗尽、进程强杀、PostgreSQL immediate restart 或提交故障注入。仓库保留这些测试与手动资格工作流，不代表它们已对本次二进制执行或通过。本次未触发完整安全/故障资格。

以下仍不能由本次普通 CI 或项目所有者的范围未说明测试报告证明：完整安全与依赖审计、Windows 11 实机、真实 SSD/物理断电、磁盘满及长期负载、ERP 业务集成、生产升级/回退、生产 SLA 与性能目标。普通逻辑备份恢复用例验证 SQL 0.1.1；默认 SQL 0.1.0 的专门逻辑恢复回归仍待补充。消息语义为至少一次，消费者需自行保证业务副作用幂等。

TTL、expiry、priority、group 等字段可随消息透传，不执行对应 broker 语义。不支持 AMQP 0-9-1、RabbitMQ exchange/binding、AMQP 事务协调器或消息级 exactly-once 业务副作用。更多边界见[源码对应的协议说明](https://github.com/MixGeeker/echoo_pgmq/blob/ef12d35447c7783f75ca123467208eb100533311/docs/protocol.md)。

### 下载后先验证

从项目的可信 GitHub Release 页面下载资产。将所需 ZIP、它的 `.sha256`、`install_candidate.py` 和 `SHA256SUMS` 放在同一新目录。在运行安装器前，先查看 `SHA256SUMS` 与 provenance 是否来自预期发布来源，再完成校验。

Linux 示例选择 PG18，其他主版本只改文件名中的 `pg18`：

```sh
set -eu
archive=echoo-pgmq-0.1.0-candidate-pg18-linux-x86_64.zip
# 精确选择本次需要的三条记录；缺少、重复或格式异常时停止。
python3 - "$archive" <<'PY'
import hashlib, pathlib, re, sys
wanted = {sys.argv[1], sys.argv[1] + '.sha256', 'install_candidate.py'}
records = {}
for line in pathlib.Path('SHA256SUMS').read_text(encoding='ascii').splitlines():
    match = re.fullmatch(r'([0-9a-fA-F]{64})  ([^/\\]+)', line)
    if not match:
        raise SystemExit('Invalid SHA256SUMS record')
    digest, name = match.groups()
    if name in records:
        raise SystemExit('Duplicate SHA256SUMS record: ' + name)
    records[name] = digest.lower()
for name in sorted(wanted):
    if name not in records:
        raise SystemExit('Missing SHA256SUMS record: ' + name)
    actual = hashlib.sha256(pathlib.Path(name).read_bytes()).hexdigest()
    if actual != records[name]:
        raise SystemExit('SHA256 mismatch: ' + name)
    print('OK:', name)
PY
sha256sum --check --strict "$archive.sha256"
```

Windows 原生 PowerShell 示例选择 PG18：

```powershell
$ErrorActionPreference = 'Stop'
$Archive = 'echoo-pgmq-0.1.0-candidate-pg18-windows-amd64.zip'
$Records = @{}
foreach ($Line in Get-Content -LiteralPath './SHA256SUMS') {
    if ($Line -notmatch '^([0-9a-fA-F]{64})  ([^/\\]+)$') {
        throw 'Invalid SHA256SUMS record'
    }
    $Digest = $Matches[1].ToLowerInvariant()
    $Name = $Matches[2]
    if ($Records.ContainsKey($Name)) { throw "Duplicate checksum: $Name" }
    $Records[$Name] = $Digest
}
foreach ($Name in @($Archive, "$Archive.sha256", 'install_candidate.py')) {
    if (!$Records.ContainsKey($Name)) { throw "Missing checksum: $Name" }
    $Actual = (Get-FileHash -Algorithm SHA256 -LiteralPath "./$Name").Hash.ToLowerInvariant()
    if ($Actual -ne $Records[$Name]) { throw "SHA256 mismatch: $Name" }
    Write-Host "OK: $Name"
}
$Sidecar = (Get-Content -Raw -LiteralPath "./$Archive.sha256").Trim()
if ($Sidecar -notmatch '^([0-9a-fA-F]{64})  (.+)$') { throw 'Invalid ZIP sidecar' }
if ($Matches[2] -cne $Archive -or $Matches[1].ToLowerInvariant() -ne $Records[$Archive]) {
    throw 'ZIP sidecar differs from release checksum'
}
```

若已下载 `SHA256SUMS` 所列的全部资产，在 Linux 还可执行 `sha256sum --check --strict SHA256SUMS` 核验整套资产。校验失败时停止，不改写清单或绕过验证。SHA-256 只能检查字节一致性；ZIP 与清单若一起被替换，散列无法独立认证发布者。本次没有代码签名或独立签名清单。

## 隔离安装

### 安装前提

1. 使用专门的可丢弃虚拟机或独立 PostgreSQL 安装，只有合成数据，与真实 ERP 集群和业务网络隔离。仅新建 PGDATA 不足以隔离：安装器修改 `pg_config` 指向的公共库和 SQL 安装目录。
2. 选择与包一致的操作系统、x86-64/x64 架构和 PostgreSQL 主版本。Linux 二进制的 CI 基线为 Ubuntu 24.04；其他发行版、glibc 或依赖组合需独立构建/验证。不可跨 PG 主版本复制 so/DLL。
3. 安装可信 PostgreSQL/系统发行版提供的 OpenSSL 3.x。包内含 Apache Qpid Proton 0.40.0，**不附带 OpenSSL**；Windows 还需匹配的 Microsoft Visual C++ Runtime/UCRT。不要从 DLL 下载站补库或覆盖 PostgreSQL 自带 OpenSSL DLL。
4. 先确认目标 `pg_config --version`、`postgres --version`、`initdb --version` 能运行。安装辅助脚本需 Python 3.12；PostgreSQL 服务本身不依赖 Python 或 Node。
5. 停止使用该 PostgreSQL 安装的全部集群和进程。确认目标安装可完全丢弃且目录可写；服务/运行用户应对库和证书有读取权限，非受信用户不得写入依赖目录。

安装器会删除并替换目标目录中的既有 Echoo 扩展、SQL/control 和 Proton 文件，再核对写入字节；它不会管理集群停止、备份或生产迁移。它只在全部校验后才开始写入，但写入过程并非事务式安装。不要对已有生产或共享 PostgreSQL 安装执行，也不要为让脚本通过而关闭校验或扩大系统权限。

### Linux

下面路径代表事先准备好的、当前用户可写的独立测试 PostgreSQL 安装，执行前改成自己的路径；不能指向仍被其他集群使用的安装：

```sh
PG_CONFIG=/opt/echoo-disposable/pgsql-18/bin/pg_config
"$PG_CONFIG" --version
python3 ./install_candidate.py \
  --archive ./echoo-pgmq-0.1.0-candidate-pg18-linux-x86_64.zip \
  --pg-config "$PG_CONFIG" --disposable-installation
```

原始归档必须和同名 `.sha256` 并排保留。安装器进一步检查 ZIP 路径与文件集合、MANIFEST 内每文件散列、平台/架构与 PG 主版本；Proton 库放在扩展库目录，由安装时 `$ORIGIN` 路径寻找。运行时另需系统提供匹配的 OpenSSL，不沿用构建机临时 `LD_LIBRARY_PATH`。

### Windows

在原生 Windows PowerShell 中使用独立、可写、已停止的测试 PostgreSQL 安装；不是 WSL：

```powershell
$ErrorActionPreference = 'Stop'
$PgConfig = 'C:/echoo-disposable/pgsql-18/bin/pg_config.exe'
& $PgConfig --version
if ($LASTEXITCODE -ne 0) { throw 'PostgreSQL prerequisite failed' }
python ./install_candidate.py `
    --archive ./echoo-pgmq-0.1.0-candidate-pg18-windows-amd64.zip `
    --pg-config $PgConfig --disposable-installation
if ($LASTEXITCODE -ne 0) { throw 'Candidate installation failed' }
```

安装器把 Proton DLL 放到目标 PostgreSQL 的 `bin`，不会复制或替换 OpenSSL/PostgreSQL DLL。服务进程的可见路径与交互式 PowerShell 不一定相同。先确认独立目标正常初始化和启动；Windows Server 2022 CI 结果不能代替 Windows 11 服务身份、NTFS 权限、防火墙、防病毒及设备验收。

### 初始化与普通验证

文件安装完成后，以普通 OS 用户初始化新的数据目录，仅监听 loopback。在测试数据库明确执行 `CREATE EXTENSION echoo_pgmq VERSION '0.1.0';`，然后按[固定源码快速开始](https://github.com/MixGeeker/echoo_pgmq/blob/ef12d35447c7783f75ca123467208eb100533311/docs/quickstart.md)的角色、专用 CA、双向 TLS 证书和 listener 配置步骤完成接入。先建角色/扩展，之后启用 listener 并正常重启。保持 `fsync`、`full_page_writes`、`synchronous_commit` 为 `on`；不以关闭耐久性或证书校验解决问题。

PG17/18 的 worker 角色保持 `NOLOGIN`；PG16 按该指南使用无密码 `LOGIN` 并在 pg_hba 最前明确拒绝 worker 的外部连接，不给业务用户 worker 成员资格。为每个客户端单独授权队列；默认仅本机监听，不开放公网。

普通自动验证应从本次固定源码归档运行 `scripts/run_integration.py --ordinary`，使用全新的工作目录及明确的测试 `pg_config`。完整命令与开发依赖见固定源码快速开始；只执行普通验证，不误触发保留的安全/故障场景。保留目录包含测试私钥和临时数据库，不上传；日志和证据分享前脱敏。

## SQL 迁移与冻结预览

默认 SQL 版本仍为 `0.1.0`。随包的 `0.1.0--0.1.1` 加法迁移及 `0.1.1` 全新安装脚本用于可选的 `queue_stats` 视图和迁移/恢复验证；它们不表示另外发布了 v0.1.1，也不是安装 v0.1.0 的必需步骤。迁移前先在隔离副本验证备份与恢复，按[固定源码升级与回退说明](https://github.com/MixGeeker/echoo_pgmq/blob/ef12d35447c7783f75ca123467208eb100533311/docs/upgrades.md)处理；没有自动 DOWN 脚本，不通过 `DROP EXTENSION` 或手改 `pg_extension.extversion` 回退。PostgreSQL 主版本升级也不由本安装器处理。

`preview-20260930.1/.2` 已发归档、guide、清单和二进制继续冻结。特别是 `.2` 包装器安装器固定了原 450681d 预览的散列，**不能拿来安装本次 ef12d354 二进制，也不能修改它的固定散列来绕过校验**。本次 Release 使用上面的独立安装路径；旧预览的 ROOT 不作为原地升级目标。本说明不承诺从预览或生产环境无停机、无损原位升级。
